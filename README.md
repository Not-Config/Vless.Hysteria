# Vless.Hysteria

Небольшой проект для быстрого развёртывания VPN-сервера на Ubuntu или Debian.

Он автоматически устанавливает и запускает два варианта подключения:

- **VLESS + REALITY + XTLS Vision** — работает по TCP;
- **Hysteria2** — работает по UDP и использует обычный QUIC/HTTP/3 без дополнительной обфускации.

Оба варианта можно использовать одновременно. Например, VLESS может работать на TCP/443, а Hysteria2 — на UDP/443. Номер порта одинаковый, но протоколы разные, поэтому они друг другу не мешают.

Главная идея проекта — чтобы сервер можно было развернуть почти одной командой и не настраивать всё вручную.

## Быстрая установка

На чистом сервере Ubuntu или Debian:

```bash
git clone https://github.com/Not-Config/Vless.Hysteria.git
cd Vless.Hysteria
sudo ./install.sh
```

Во время установки скрипт спросит основные параметры: внешний IP или домен, порты, REALITY SNI/target, TLS fingerprint и имя первого пользователя.

После этого он сам:

1. установит Docker и Docker Compose, если их ещё нет;
2. скачает Xray и Hysteria2;
3. сгенерирует UUID, ключи REALITY и пароли;
4. создаст сертификат для Hysteria2;
5. создаст первого пользователя;
6. соберёт конфиги;
7. запустит оба контейнера;
8. включит автоматическую проверку работы сервисов;
9. выведет готовые ссылки `vless://` и `hy2://` для импорта в клиент.

Все рабочие файлы после установки находятся здесь:

```text
/opt/vless-hysteria/
```

## Что получается после установки

По умолчанию схема выглядит так:

```text
TCP/443 -> VLESS + REALITY
UDP/443 -> Hysteria2 (QUIC / HTTP/3)
```

Для VLESS используется REALITY. У него можно отдельно выбрать настоящий TLS 1.3 target/SNI и TLS ClientHello fingerprint клиента. Поддерживаются `chrome`, `firefox`, `safari`, `ios`, `android`, `edge`, `360`, `qq`, `random` и `randomized`. По умолчанию используется `chrome`.

Это обычная настройка маскировки и совместимости REALITY: target должен быть реальным TLS 1.3-сайтом, который нормально отвечает с выбранным SNI. Скрипт проверяет доступность TLS 1.3 перед запуском.

Hysteria2 настроена без Salamander. Поэтому её трафик остаётся обычным QUIC/HTTP/3, а при обычном HTTP/3-запросе сервер использует `masquerade` и отдаёт содержимое указанного сайта через reverse proxy.

Важно: это не делает сервер полностью невидимым. Для правдоподобной работы как обычного сайта на публичном VPS лучше использовать реальный домен и нормальный TLS-сертификат. В учебной конфигурации пока используется локально созданный сертификат с SHA-256 pinning.

## Управление

Проверить состояние:

```bash
sudo /opt/vless-hysteria/status.sh
```

Добавить нового пользователя:

```bash
sudo /opt/vless-hysteria/user.sh add user
```

Показать ссылки пользователя:

```bash
sudo /opt/vless-hysteria/user.sh links user
```

Показать список пользователей:

```bash
sudo /opt/vless-hysteria/user.sh list
```

Удалить пользователя:

```bash
sudo /opt/vless-hysteria/user.sh remove user
```

Изменить основные настройки:

```bash
sudo /opt/vless-hysteria/configure.sh
```

Запустить диагностику:

```bash
sudo /opt/vless-hysteria/diagnostics.sh
```

Создать резервную копию:

```bash
sudo /opt/vless-hysteria/backup.sh
```

Обновить контейнеры:

```bash
sudo /opt/vless-hysteria/update.sh
```

Удалить проект с сервера:

```bash
sudo /opt/vless-hysteria/uninstall.sh
```

## Если сервер находится за роутером

Если сервер стоит дома или в локальной сети, одного запуска скрипта недостаточно. Нужно ещё пробросить порты на роутере.

Например:

```text
Внешний TCP/8443 -> сервер TCP/443 -> VLESS
Внешний UDP/8443 -> сервер UDP/443 -> Hysteria2
```

При установке можно указать внешний порт отдельно от порта, на котором сервис слушает внутри сервера.

Если это обычный VPS с публичным IP, чаще всего достаточно открыть нужные TCP/UDP-порты в firewall.

## Где хранятся настройки

Обычные настройки находятся в:

```text
/opt/vless-hysteria/.env
```

Секретные ключи и пароли находятся отдельно:

```text
/opt/vless-hysteria/secrets.env
/opt/vless-hysteria/users.json
```

Эти файлы не должны публиковаться в GitHub.

Сам репозиторий не содержит готовых паролей, UUID или приватных ключей. Они создаются прямо на сервере во время установки.

## Автоматическая проверка

После установки включается watchdog. Он раз в минуту проверяет:

- работает ли контейнер Xray;
- работает ли контейнер Hysteria2;
- слушается ли TCP-порт VLESS;
- слушается ли UDP-порт Hysteria2.

Если какой-то сервис перестал работать, watchdog попробует его перезапустить.

Проверить watchdog можно так:

```bash
systemctl status vless-hysteria-watchdog.timer
```

## Для чего этот проект

Проект сделан как простой и переносимый вариант развёртывания VPN-сервера. Его можно запустить на виртуальной машине, домашнем сервере или VPS.

Основная цель — не настраивать Xray и Hysteria2 вручную каждый раз, а получить одинаковую рабочую конфигурацию через один установочный скрипт.
